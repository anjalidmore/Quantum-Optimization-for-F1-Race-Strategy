## The "no fabricated results" check

Start here, because it determines how much you trust everything else. README §8
claims no value in this project is hand-written. That was tested adversarially:

```
TRACE 1  API /api/ml/metrics  →  artifacts/metrics/regression_metrics.json
   decision_tree   API=0.8673476599610876  DISK=0.8673476599610876  match=True
   random_forest   API=0.9253493148742147  DISK=0.9253493148742147  match=True

TRACE 2  API best_model='decision_tree'  →  model_registry.json ['decision_tree']

TRACE 3  MUTATION TEST
   set the on-disk MAE to 999.123456  →  the API returned 999.123456
   VERDICT: reads from the artifact, not a hard-coded constant
```

The third one is the one that matters. A matching value proves nothing on its
own — a constant could coincide. Changing the artifact and watching the API
follow proves the read path is real.

Corroborating evidence: a full `scripts/build_all.py --force` rebuild reproduced
every committed artifact, with entity counts, rule counts and search costs
**identical** and ML metrics agreeing to ~1e-14.

## 1. The Explainability page — why you should believe any of this ⭐

`/explainability` (or `artifacts/reports/xai_explainability_dashboard.md`)

Every other page shows you a number. This one shows you where the number came from and
how much to trust it. A real sentence generated by the pipeline from real SHAP values:

> *"Recommend STAYING OUT — model confidence 28%. Tyre age (26) is the dominant factor
> pushing towards a stop; current form against this driver's baseline (0.2766) is a
> moderate factor pushing towards a stop; race progress (0.9636) is a minor factor
> pushing against stopping. Trust in this recommendation: MODERATE."*

Three things worth a minute each:

* **The fairness assessment.** Task 5's real-data contract kept **28 driver/team identity
  dummies out of 45** regression features — so "is this model predicting *who* is driving
  rather than *what the car is doing*?" is a real question, not a hypothetical one. The
  answer is measured, not asserted: identity's share of total |SHAP| attribution against
  what an even spread would give. 📄 `artifacts/reports/xai_fairness_report.md`
* **The trust score.** An explicit formula — `0.40·confidence + 0.30·model_agreement +
  0.30·explanation_stability` — with the reasoning for each weight, and bands that tell a
  race engineer what to *do*. It penalises SHAP and LIME disagreeing about *why*, not just
  the models disagreeing about *what*. 📄 `artifacts/reports/xai_trust_score_report.md`
* **The honest negative.** Sweeping tyre age across its entire observed range with the
  rest of the race state fixed never flips the call. Reported as *not reachable* with the
  range searched, rather than papered over.
  📄 `artifacts/reports/xai_counterfactual_report.md`

## 2. The Deep Learning page — a comparison that could have gone either way

`/deep-learning` (or `artifacts/reports/dl_evaluation_report.md`)

Two Keras networks trained on the **same folds, same holdout and same metric code** as
Task 6's classical models — `app/intelligence/dl/` imports
`app.intelligence.ml.splits` and `.evaluation` directly rather than copying them, so any
difference in the table is attributable to the model rather than the harness. The
classical rows are read from Task 6's own committed `artifacts/metrics/*.json`.

What makes it worth reading is the framing rather than the winner: the report states the
**parameters-to-training-rows ratio**, names all three overfitting countermeasures and how
many epochs early stopping actually discarded, and documents why models ship as `.keras`
rather than the spec's `.h5` (Keras 3 saves HDF5 but cannot reload it).

🖼️ `artifacts/figures/dl_target_laptime_training_history.png` — loss curves with the
restored epoch marked.

## 3. `POST /api/strategy/predict` — the integration payoff

One endpoint, three reasoning paradigms, one answer. This is the thing the whole
architecture exists to make possible:

```json
{
  "predicted_lap_time_seconds": 102.85834374999999,
  "probability_pit": 0.5622544303893682,
  "recommended_action": "PIT_NOW",
  "expected_cost_seconds": 3286.8485,
  "triggered_expert_rules": ["R-TYRE-002", "R-RISK-002"],
  "data_source": "real_fastf1"
}
```

The lap time comes from a trained regressor, `triggered_expert_rules` from the
symbolic rule engine, and `expected_cost_seconds` from A\* search over the pit
state space. Most student projects implement these three and leave them in
separate folders. Here they compose.

📄 `app/services/strategy_service.py` · try it at `/docs` once the API is up.

## 6. Leakage prevention, done properly

The single most common failure in student ML projects, handled explicitly here:

* 📄 `data/processed/feature_metadata.json` — `excluded_as_leakage` lists six
  columns with the reason. The sector-time identity (they sum exactly to
  `LapTime`) is demonstrated **numerically** in the notebook before exclusion,
  not merely asserted.
* Splits are **expanding-window, lap-forward**, keeping whole laps in one fold —
  not random K-fold, which would leak future laps into training on a
  time-ordered panel.
* Scaling is fitted **inside** each CV fold. Task 5 deliberately exports
  *unscaled* features and records which columns need scaling, so the modelling
  stage cannot accidentally leak test-fold statistics.

📄 `app/intelligence/ml/splits.py` · `app/intelligence/ml/preprocessing.py`
· 🧪 `tests/test_ml_splits.py`, `tests/test_ml_data_contract.py`

## What this project is honest about

* **Tasks 9–10 and the quantum work do not exist yet.** The name promises
  quantum optimisation; the repository delivers a classical platform built to
  receive it. The README status table says so.
* **Deep learning does not automatically win.** Task 7's report states which model
  actually won per target and why, including where the classical model was better. On a
  single race session that is the expected outcome, and tuning the comparison to flatter
  the network would defeat the point of running it.
* **Three engine dashboard pages are not built** (Knowledge Representation,
  Expert System, Search have no dedicated page — only the Evidence index).
* **`build_all.py`'s Task 5 stage is a presence check, not a build step** — see
  [FLOW.md](FLOW.md#the-one-thing-to-be-careful-about).
* **The test suite is not hermetic** — it rewrites 10 committed artifact files.
  Reproducibly, but it does dirty a clean clone.

Known gaps are tracked in `TODO.md`, which lives on the **`proj-mode`** branch only —
it is a working backlog, deliberately kept off `main`.
