# SHOWCASE — what to look at first

Five minutes, in order. Every file referenced here is generated by running the
practical above it, so if a path is missing, run that practical's entry point
first (see [README.md](README.md#running-a-practical)).

## 1. Practical 07 — Explainable AI ⭐ start here

**The newest work, and the one that most changes what this repository is.** Every other
practical produces a number; this one explains where the number came from and tells you
how much to trust it.

📄 `practicals/practical07/outputs/reports/explainability_dashboard.md`

A real sentence generated by the pipeline from real SHAP values:

> *"Recommend STAYING OUT — model confidence 28%. Tyre age (26) is the dominant factor
> pushing towards a stop; current form against this driver's baseline (0.2766) is a
> moderate factor pushing towards a stop; race progress (0.9636) is a minor factor
> pushing against stopping. Trust in this recommendation: MODERATE."*

Three things worth 30 seconds each:

* 📄 `outputs/reports/fairness_report.md` — is the model predicting from race state, or
  from *who is driving*? Measured as identity's share of total |SHAP| attribution against
  what an even spread would give. Here: **2.1%** against 16.7% expected — race-state
  features dominate, which is the desired answer.
* 📄 `outputs/reports/trust_score_report.md` — an explicit formula
  (`0.40·confidence + 0.30·model_agreement + 0.30·explanation_stability`) with the
  reasoning for each weight and worked examples.
* 📄 `outputs/reports/counterfactual_report.md` — and the honest negative: sweeping tyre
  age across its whole observed range never flips the call, reported as *not reachable*
  with the range searched, rather than papered over.

## 2. Practical 06 — Deep Learning

📄 `practicals/practical06/outputs/reports/dl_evaluation_report.md`

| Model | MAE (s) | R² |
|---|---:|---:|
| **`dnn_mlp`** | **0.1584** | **0.7631** |
| random_forest | 0.2298 | 0.5509 |
| mean_baseline | 0.4645 | −0.5398 |

The network wins lap-time regression by 31%. It then **loses** the pit decision — CV
ROC-AUC 0.4178, worse than chance on 16 positive examples — and the report says so
plainly instead of quietly dropping the target.

Worth reading for the engineering, not just the result: the report states the
parameters-to-training-rows ratio (**6.10**), names all three overfitting countermeasures
with the epochs early stopping actually discarded, and documents why `.keras` ships
instead of the spec's `.h5` (Keras 3 saves HDF5 but cannot reload it).

🖼️ `outputs/figures/target_laptime_training_history.png` — loss curves with the restored
epoch marked.

## 3. Practical 03 — State-Space Search

**The single most convincing artifact in this branch.** Five search algorithms
solve the same pit-strategy problem and are measured head-to-head — and the
result includes a *falsifiable correctness claim*, not just output.

📄 `practicals/practical03/outputs/reports/comparison_report.md`

| Algorithm | Cost (s) | Optimal | Expanded | Time (ms) |
|---|---|---|---|---|
| BFS | 2270.66 | | 1455 | 14.13 |
| DFS | 2299.93 | | 24 | 0.15 |
| UCS | **2262.42** | ★ | 1589 | 19.45 |
| Greedy | 2270.66 | | 26 | 0.52 |
| A\* | **2262.42** | ★ | 1005 | 13.76 |

A\* and UCS agree to the cent, and A\* gets there expanding 37% fewer nodes —
which is exactly what an admissible heuristic is supposed to buy you. The run
asserts this invariant and fails loudly if it ever breaks:

```
Optimality invariant holds: A* cost == UCS cost == 2262.42 s
```

Also worth 30 seconds: 🖼️ `outputs/diagrams/optimal_strategy_path.png` (the
winning stint plan) and 📄 `outputs/reports/state_space_formulation.md` (the
formal ⟨state, actions, cost, goal, heuristic⟩ statement).

## 6. Practical 05 — Feature Engineering

📓 `practicals/practical05/practical05.ipynb`

Skip to **§ leakage** and **§ the selection funnel**. Two things a reviewer
should notice:

* **Leakage is demonstrated, not asserted.** The notebook proves numerically
  that the three sector times sum exactly to `LapTime` before excluding them,
  rather than just claiming they leak. Six columns are excluded on that basis.
* **Scaling is deliberately *not* applied.** The exported features are unscaled,
  and `feature_metadata.json` records which columns need scaling — so the
  downstream task can fit the scaler *inside* each CV fold. Scaling here would
  leak test-fold statistics into training. That restraint is the point.

📄 `practicals/practical05/outputs/feature_metadata.json` — the full contract:
selected features per target, per-feature provenance, the four-stage selection
funnel, the preprocessing rules, and a `caveat` field stating plainly that the
classification AUC is inflated by the synthetic session's near-deterministic
pit schedule.

## What this branch is honest about

The input *data* is synthetic by default (real code, real schemas, generated
rows) so everything runs offline — and the consequences are stated rather than buried:
an inflated pit-decision AUC in practical 05's own metadata; **zero positive examples in
practical 06's holdout**, making ROC-AUC undefined there for every model alike; and a
fairness assessment that is mild on this branch only because the synthetic contract keeps
1 identity feature per target where the real-data contract keeps 28 of 45. See
[FLOW.md](FLOW.md#what-is-real-vs-what-is-synthetic).

Practical 06 also documents a bug it hit and fixed: the first run reported an MAE of
29 seconds and an R² of −5949 because the lap-time target (mean 91 s, σ 0.56 s) was fed
to a linear output head unscaled. That is in the README as a worked example, not
airbrushed out.
