## 1. Practical 03 — State-Space Search ⭐ start here

**The single most convincing artifact in this branch.** Five search algorithms
solve the same pit-strategy problem and are measured head-to-head — and the
result includes a *falsifiable correctness claim*, not just output.

📄 `practicals/practical03/outputs/reports/comparison_report.md`

| Algorithm | Cost (s) | Optimal | Expanded | Time (ms) |
|---|---|---|---|---|
| BFS | 2270.66 | | 1455 | 14.13 |
| DFS | 2299.93 | | 24 | 0.15 |
| UCS | **2262.42** | ★ | 1589 | 19.45 |
| Greedy | 2270.66 | | 26 | 0.52 |
| A\* | **2262.42** | ★ | 1005 | 13.76 |

A\* and UCS agree to the cent, and A\* gets there expanding 37% fewer nodes —
which is exactly what an admissible heuristic is supposed to buy you. The run
asserts this invariant and fails loudly if it ever breaks:

```
Optimality invariant holds: A* cost == UCS cost == 2262.42 s
```

Also worth 30 seconds: 🖼️ `outputs/diagrams/optimal_strategy_path.png` (the
winning stint plan) and 📄 `outputs/reports/state_space_formulation.md` (the
formal ⟨state, actions, cost, goal, heuristic⟩ statement).

## 4. Practical 05 — Feature Engineering

📓 `practicals/practical05/practical05.ipynb`

Skip to **§ leakage** and **§ the selection funnel**. Two things a reviewer
should notice:

* **Leakage is demonstrated, not asserted.** The notebook proves numerically
  that the three sector times sum exactly to `LapTime` before excluding them,
  rather than just claiming they leak. Six columns are excluded on that basis.
* **Scaling is deliberately *not* applied.** The exported features are unscaled,
  and `feature_metadata.json` records which columns need scaling — so the
  downstream task can fit the scaler *inside* each CV fold. Scaling here would
  leak test-fold statistics into training. That restraint is the point.

📄 `practicals/practical05/outputs/feature_metadata.json` — the full contract:
selected features per target, per-feature provenance, the four-stage selection
funnel, the preprocessing rules, and a `caveat` field stating plainly that the
classification AUC is inflated by the synthetic session's near-deterministic
pit schedule.

## What this branch is honest about

The input *data* is synthetic by default (real code, real schemas, generated
rows) so everything runs offline — and the consequence, an inflated pit-decision
AUC, is stated in the notebook's own metadata rather than buried. See
[FLOW.md](FLOW.md#what-is-real-vs-what-is-synthetic).
