# Phase 3 · Task 8 — Explainable AI

Part of **Quantum Optimization for Formula 1 Race Strategy**.

> **Scope of this module:** interpreting the models Task 6 and Task 7 produced. No new
> models are trained here. The goal is that a **race engineer** — not a data scientist —
> can see *why* a strategy recommendation was made and decide how much to trust it.

---

## 1. What this module does

Every prediction from the Task 7 deep network and its classical counterpart is
decomposed into named, quantified factors, then scored for trustworthiness.

## 2. The seven techniques, and why each is here

| Step | Method | Why this one |
|---|---|---|
| Global importance | **Permutation importance** | The only method that means the *same thing* for a random forest and a Keras network. A tree's Gini importance and a network's gradients are not comparable; "how much worse does the model get if I shuffle this column?" is. |
| Attribution (classical) | **SHAP `TreeExplainer`** | *Exact* Shapley values for tree ensembles, in polynomial time. Free accuracy — always prefer it when the model is a tree. |
| Attribution (deep) | **SHAP `KernelExplainer`** | Model-agnostic; needs only a `predict` function. `DeepExplainer`'s Keras 3 support targets the TensorFlow backend, and this project runs Keras on PyTorch. |
| Local surrogate | **LIME** | A second, independent account of the same prediction. When it disagrees with SHAP, that disagreement is itself a signal — and the trust score uses it as one. |
| Counterfactual | **Single-feature bisection scan** | Answers the question an engineer actually asks: *how many more laps on these tyres before the call changes?* One actionable number. |
| Counterfactual | **DiCE (random search)** | Whole-row alternatives, for when several routes to a different call exist. Bounded to a 60-second budget (see §5). |
| Fairness | **Identity-attribution share** | Measures whether the model predicts from *race state* or from *who is driving*. |

### SHAP vs LIME — the distinction that matters

|  | SHAP | LIME |
|---|---|---|
| Question | How is credit for this prediction fairly divided? | What simple model behaves like the real one *around here*? |
| Basis | Shapley values (cooperative game theory) | Local weighted linear regression |
| Guarantee | Attributions sum to (prediction − base value) | None; quality reported as the surrogate's R² |

They usually agree on *which* features matter. When they don't, the local decision
surface isn't well approximated by a line — and the trust score penalises exactly that.

## 3. Results (measured on the untouched test set)

### Fairness — the headline finding on this branch

| Target | Identity features | Share of attribution | If uniform | Concentration |
|---|---|---:|---:|---:|
| `target_laptime` | 1 of 6 (`driver_sai`) | **2.1%** | 16.7% | **0.12×** |
| `target_pit_next_lap` | 1 of 8 (`team_aston_martin`) | **3.7%** | 12.5% | **0.30×** |

**Both models are well below an even spread.** Race-state features — `tyre_life`,
`gap_expanding`, `field_median_lag1`, `race_progress` — dominate the reasoning, which is
the desired outcome. Identity is carrying *less* weight than its share of the feature
count, not more.

> **This result is specific to `task-mode`.** practical05's synthetic contract selected
> only **1** identity feature per target. The `proj-mode` branch's real-data contract
> selects **28 driver/team dummies out of 45** regression features — a far higher
> exposure, and where this assessment does real work. The same code runs there.

### Trust scores

| Target | Rows explained | Mean trust | Bands |
|---|---:|---:|---|
| `target_laptime` | 3 | 0.738 | 2 HIGH, 1 MODERATE |
| `target_pit_next_lap` | 2 | 0.736 | 1 HIGH, 1 MODERATE |

### A real strategic explanation, generated by the pipeline

> *"Recommend STAYING OUT — model confidence 28%. Tyre age (26) is the dominant factor
> pushing towards a stop; current form against this driver's baseline (0.2766) is a
> moderate factor pushing towards a stop; race progress (0.9636) is a minor factor
> pushing against stopping. Trust in this recommendation: MODERATE."*

That sentence is assembled from real SHAP values and the row's real feature values. The
glossary in `src/f1xai/narrative.py` maps every feature to plain English, and any feature
missing from it falls back to a readable form of its own name rather than being silently
dropped from the explanation.

## 4. The trust score

```
trust = 0.40 · confidence
      + 0.30 · model_agreement
      + 0.30 · explanation_stability
```

| Component | Definition | Why it's here |
|---|---|---|
| `confidence` | Classification: `2·\|p − 0.5\|`. Regression: `1 − min(1, gap/σ)`. | A prediction on the decision boundary is unusable however well explained. |
| `model_agreement` | `1 − \|p_dnn − p_classical\|` | Two model families trained on identical folds agreeing is real evidence. One disagreeing means at least one is wrong and you can't tell which. |
| `explanation_stability` | Jaccard overlap of SHAP's and LIME's top-3 | If two established methods disagree about *why*, the explanation you'd show the engineer isn't trustworthy even when the prediction is right. |

**Bands:** ≥0.75 HIGH (safe to act on) · 0.50–0.75 MODERATE (read the factors first) ·
0.25–0.50 LOW (look at the evidence, not the recommendation) · <0.25 DO NOT ACT.

The weights are a **judgement, not a derivation** — confidence carries the largest share
because boundary predictions are useless regardless of explanation quality. They're
exposed as `f1xai.trust.WEIGHTS` so they can be challenged and changed.

## 5. Two honest limitations

**The counterfactual scan finds no reachable flip on this data.** Sweeping `tyre_life`
across its full observed range (1–27 laps) with the rest of the race state held fixed
never crosses the decision threshold, for any explained row. That is reported as
*not reachable*, with the range searched — not patched around. It means the synthetic
session's decisions are driven by feature *combinations* rather than tyre age alone.

**DiCE needed a hard time budget.** Its random search samples until it finds an
opposite-class row; with pit events at 4.8% prevalence, an early run sampled for
**15 minutes and returned nothing**. It is now bounded to 60 seconds, queried from the
row closest to the decision boundary (where a flip is most likely reachable), and
restricted to each feature's observed training range. It now returns 3 counterfactuals in
about a second. If the budget is ever exceeded, the report says so explicitly.

## 6. Prerequisites & running

**Run practical05 and practical06 first** — Task 8 explains Task 7's models.

```bash
cd practicals/practical07
pip install -r requirements.txt
python practical07.py                 # full run, ~2 minutes
python practical07.py --quick         # fast smoke run (NOT the committed results)
pytest -q                             # 38 tests
```

Determinism: SHAP's KernelExplainer, LIME's perturbation sampling and DiCE's search are
all seeded (`RANDOM_STATE = 42`), and a test asserts LIME returns identical weights across
two runs with the same seed.
